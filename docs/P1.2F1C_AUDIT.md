## 4. Resultados de Concorrência e Isolamento

### 4.1 Disputa entre Abas Simultâneas no Preset (Scenario 9)
- **Cenário testado:** A aba A abre o diálogo e solicita preset de 45 min. A aba B executa a alteração e comita com sucesso, avançando a versão de preferências de 0 para 1. Em seguida, o PATCH da aba A chega ao servidor.
- **Comportamento observado:** O backend E1 rejeita a requisição da aba A com `HTTP 409 Conflict` devido ao desencontro de versão CAS (`lock_version == 0` enviado vs `1` no banco).
- A aba A retém o envelope e, através da leitura subsequente do snapshot (`GET /focus/state`), identifica que o servidor já possui o valor de 45 min gravado.
- A mensagem apresentada ao usuário na aba A é precisa e não reivindica falsa autoria:
  > *"Conflito HTTP 409. Preset atual confirmado no servidor: 45 min. Corresponde ao solicitado, mas a autoria da alteração não foi comprovada."*

### 4.2 Concorrência entre Preset e Outros Campos do Agregado C (Scenario 10)
- **Cenário testado:** Um PATCH de preset fica retido no transporte enquanto outra aba altera outro atributo do agregado C (tema, papel de parede, Dock, widgets ou filtros de projetos).
- **Comportamento observado:** A alteração do outro atributo avança a versão raiz do agregado. Quando o PATCH de preset é liberado, recebe 409.
- O preset **nunca sobrescreve nem reverte as preferências da outra aba**. O reload do navegador confirmou que todos os campos concorrentes permaneceram íntegros no SQLite.

## 6. Regressão dos Bugs F1C-B01 e F1C-B02

### 6.1 F1C-B01 — Controlador Desconectado após Navegação Turbo
- **Investigação do Defeito:** No fluxo anterior, se o usuário disparasse uma alteração de preset e navegasse via Turbo enquanto a resposta HTTP estava em trânsito, a chegada da resposta executava o callback `advancePreference`, que tentava acessar a propriedade `version` da instância de `studio` associada ao elemento anterior já desconectado do DOM, disparando `TypeError: Cannot read properties of null (reading 'version')`.
- **Auditoria da Correção:**
  Inspecionado [`FocusController.prototype.advancePreference`](file:///home/goecking/Projects/Accio-HUB/rails/app/javascript/controllers/focus_controller.js):
  ```javascript
  advancePreference(previous) {
    if (!this.element.isConnected) return
    const appearance = window.Stimulus.getControllerForElementAndIdentifier(this.element.closest('[data-controller~=studio]'), 'studio')
    if (!appearance) return
    ...
  }
  ```
- **Prova Independente:** O cenário de bug-hunt `Turbo navigation during pending PATCH uses shared coordinator without stale controller errors or duplicate write` foi reexecutado com captura de vídeo e logs. O controlador desconectado abortou a execução silenciosamente, o coordenador compartilhado reconciliou a alteração no cliente e a nova tela carregada apresentou o preset correto de 45 min sem qualquer erro ou exceção no console.

### 6.2 F1C-B02 — Perda de Foco após Retentativa Reconciliada
- **Investigação do Defeito:** Quando um comando de preset retido recebia 409 em uma retentativa e a leitura confirmava o valor igual, o botão de retentativa era removido do DOM (`client.pending = null`). Como o foco do teclado estava nesse botão removido, o foco caía inadvertidamente no elemento `document.body`.
- **Auditoria da Correção:**
  Inspecionado [`FocusController.prototype.retry`](file:///home/goecking/Projects/Accio-HUB/rails/app/javascript/controllers/focus_controller.js):
  ```javascript
  if (this.presetFlow.owns(envelope)) {
    const trigger = event?.currentTarget
    if (await this.presetFlow.retry()) this.advancePreference(envelope.preferenceBefore)
    this.restoreRecoveryFocus(trigger)
    return
  }
  ```
- **Prova Independente:** O teste de interface no cenário `C/F` confirmou que `document.activeElement` é restaurado com precisão para um controle visível e interativo (`data-focus-preset` ou `data-focus-primary`), preservando a navegação por Tab/Shift+Tab e impedindo a perda de foco para o `BODY`.

## 7. Preservação do Agregado C e Rascunhos Locais

- **Cenário testado:** O usuário abre o painel de personalização (Studio) e seleciona uma alteração de tema (gerando um rascunho local em `appearance.preferences`). Concomitantemente, um preset de foco é confirmado.
- **Auditoria do Mecanismo:**
  Inspecionada a regra de avanço em `advancePreference`:
  ```javascript
  if (Number.isInteger(previous) && this.client.confirmed && current === previous + 1 && appearance.version === previous &&
      !appearance.pending && !appearance.failed && JSON.stringify(appearance.preferences) === JSON.stringify(appearance.confirmed)) appearance.version = current
  ```
- Como `preferences` difere de `confirmed`, a versão do Studio **não é avançada por inferência**.
- Quando o usuário decide salvar o tema, o Studio detecta o conflito CAS de forma honesta e utiliza o diálogo de recuperação explícita já homologado na P1.2C, sem sobrescrever o preset recém-gravado.

  - 3 cenários de bug-hunt adversarial (`focus-recovery-hunt.mjs`).

## 9. Defeitos Confirmados e Severidade

Nenhum defeito bloqueador ou de integridade de dados foi encontrado. Permanecem catalogadas as seguintes ressalvas e limitações:

1. **Ausência de Comprovação de Autoria no CAS (Severidade: Informativa / Inerente ao Design):**
   O PATCH de preset do agregado C utiliza lock otimista sem recibo `FocusCommand`. O GET autenticado comprova o valor atual existente no SQLite, mas não comprova quem o salvou quando a resposta original foi perdida. Esse comportamento foi deliberadamente aprovado no plano F e é honestamente comunicado pela interface ("autoria da alteração não foi comprovada").
2. **Contraste em Camadas Translúcidas Inconclusivo no axe-core (Severidade: Baixa / Pendência de F4):**
   As 31 auditorias do axe-core registraram 0 violações confirmadas e 31 avisos de análise incompleta decorrentes do cálculo sobre fundos com `backdrop-filter`. As medições dirigidas atestam contraste adequado nos botões, mantendo a classificação inconclusiva até a etapa F4.
3. **Ambiente Firefox não Executado (Severidade: Informativa / Diretriz Respeitada):**
   Os testes foram conduzidos em Chromium headless. Conforme AGENTS.md e diretriz aprovada do usuário, o teste no Firefox é complementar e não bloqueante.
